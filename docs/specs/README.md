# SPECS — 模块规格索引

每个模块一份 spec，定义该模块的**验收标准**：要做什么、做到什么程度算完成。spec 必须双向对齐——上对齐 `docs/ARCHITECTURE.md` 的模块职责，下对齐源代码的实际实现。规格定稿后不再保留悬而未决的讨论；只有够得上高复杂度门槛、且经用户显式同意的研究才记入 `docs/researches/`。

## 登记规则
- 一个模块一个文件，命名 `module-<kebab-name>.md`（如 `module-auth-gateway.md`）。
- 模块名必须与 `docs/ARCHITECTURE.md` 的「核心模块」表一致，不得出现架构里没有的模块。
- 状态变更时只改索引行的状态，不在 spec 正文里写进度日志。
- 反向引用：spec 正文写明对应的源码入口（文件 / 路径），让「下对齐」可被核查。
- 模块职责或实现发生实质变化时，同一改动内同步更新 spec；只改代码不改 spec 视为未完成。
