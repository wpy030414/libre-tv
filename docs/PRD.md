# PRD — libre-tv（tvOS 风格视频聚合）

## 产品目标
- 要达成的目标：在电视大屏（或浏览器投屏）上获得 Apple TV 般的浏览与观看体验，内容源可插拔，新增一个源不需要动前端。

## 用户与使用场景
- 目标用户：自托管个人使用者（单运营者，无多租户诉求）。
- 典型场景：躺在客厅用遥控器/方向键翻看聚合片库；按标签/分类浏览 hanime1 内容；从任意设备续看（进度存服务端）。

## 核心问题
- 要解决的关键问题：① 源站界面不适合电视与遥控器操作；② 各源站数据结构互不兼容，前端无法直接消费；③ 浏览器直连源站受跨域与防盗链限制。

## 功能及其意义
| 功能 | 解决什么 | 为什么需要 |
|------|----------|------------|
| tvOS 风格界面（大图卡片、焦点导航、毛玻璃层） | 问题① | 电视场景的核心体验就是「焦点 + 大图 + 少文字」 |
| 源适配层（SourceAdapter 统一契约） | 问题② | 源的差异收敛在后端，前端只写一次界面 |
| 服务端代理（HTML 解析 / m3u8 代理） | 问题③ | 跨域与防盗链只能在服务端解决 |
| hanime1 源（首个适配器） | 验证契约可行性 | 用户指定的第一个真实源，无官方 API，全靠解析 |
| 播放与续看（SQLite 存进度/收藏） | 基础观看闭环 | 没有进度的电视端等于每次从零开始 |
| 双播模式：CDN 直放 / 后端下载转本地 | 源站直链不稳定（签名过期、防盗链、被墙） | 能直连就直连省带宽；不能就整片下载入库，之后本地播放 |
| 下载归档（视频 + 全量元数据 + 封面） | 离线观看与收藏长期可用 | 源站删稿/改版后仍可看；元数据必须随片保存才能离线展示与检索 |
| 在线 / 离线模式切换 | 弱网或断网时仍可用 | 离线模式只读本地库，不发起任何源站请求 |

## 功能之间的关系
- 源适配层是地基：界面（列表/搜索/详情/播放）全部消费它的归一化输出；进度/收藏以 `source + id` 为键挂在归一化实体上，与具体源解耦。
- 播放器的两档来源（CDN 直放 / 本地文件）由同一个「媒体来源解析」决定：详情页优先直放流代理，失败或用户手动下载后切换本地文件；离线模式下只解析本地文件。
- 下载任务依赖源适配层取全量元数据（详情 + 清晰度列表 + 相关推荐可选），产物是一条本地库记录，与源站后续变化解耦。

## 范围与非目标
- 范围内：浏览/搜索/详情/播放四类页面、多源注册、hanime1 适配器、播放进度与收藏、双播模式（直放/下载）、下载归档与在线/离线切换。
- 范围外：多清晰度批量下载、断点续传的跨重启恢复（单次进程内续传即可）、字幕轨合并、公网多用户部署、SSR/SEO。
